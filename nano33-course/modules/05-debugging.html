When the system breaks

Debugging this project is like checking a chain of adapters: camera, firmware, model, serial link, and viewer each have their own failure shape.

Use the built-in checkpoints

A good smoke test does not need to prove perfection. It should tell you which part of the chain is alive before you chase deeper problems.

The upload script protects RAM

RAM is one of the tightest constraints in this repository. The upload script parses Arduino compile output and blocks unsafe builds.

CODE 
if (( DYNAMIC_BYTES > RAM_MAX_BYTES )); then
  echo "ERROR: dynamic memory ${DYNAMIC_BYTES} exceeds hard limit ${RAM_MAX_BYTES}." >&2
  echo "Re-export the Edge Impulse model with a smaller arena before uploading." >&2
  exit 1
fi
PLAIN ENGLISH

If the compiled firmware uses more dynamic memory than the hard limit...

print an error that includes the measured bytes and the allowed maximum.

tell the human the likely fix: export a smaller Edge Impulse arena.

stop the script so unsafe firmware is not uploaded.

!
Common AI Mistake

If an AI assistant suggests removing memory limits to make upload pass, push back. The limit is protecting hardware behavior, not merely making the script strict.

Spot a real command mismatch

This is the kind of bug that appears when two files disagree about the protocol. The firmware uses lowercase c for calibrated exposure, while uppercase C runs a single count.

Which line makes calibrated mode send the wrong firmware command?

1 mode_cmd = {"auto": b"A", "face": b"F", "calibrated": b"C", "stream": b"S"}
2 if args.mode in mode_cmd:
3 ser.write(mode_cmd[args.mode])
4 print(f"Sent mode command: {args.mode}")

The root cause is the dictionary value for calibrated mode. This is a protocol mismatch: one side says C means count, the other side tries to use C for calibration.
